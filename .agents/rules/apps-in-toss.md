# 앱인토스 (Apps in Toss) 프로젝트 규칙

이 프로젝트는 토스(Toss) 앱 내에서 실행되는 **앱인토스 미니앱**입니다. 모든 코드 작성, UI 구현, 텍스트 작성 시 아래 규칙을 반드시 준수해야 합니다.

## 1. 아키텍처 & 프레임워크
- **렌더링**: 반드시 CSR(Client-Side Rendering) 또는 SSG 방식만 사용합니다. SSR은 지원되지 않습니다.
- **보안**: `eval()`, 동적 외부 스크립트 로드, `window.location.replace`를 통한 임의 리다이렉트는 절대 금지됩니다.
- **SDK 호출**: `@apps-in-toss/web-framework`의 최신 도메인 API(`User`, `Storage`, `Screen`, `SafeArea`, `TossAuth`, `TossPay`, `IAP`, `TossAds`, `Analytics`, `Share`, `Device`)를 사용합니다.
- **스토리지**: 브라우저 기본 `localStorage` 대신 SDK의 `Storage` API(`getItem`, `setItem`, `removeItem`)를 사용하여 버전 호환성을 보장합니다.

## 2. UI / UX 및 다크패턴 방지 (심사 필수 요건)
- **진입 직후 팝업/바텀시트 금지**: 서비스 진입 시점에 동의나 혜택 유도 바텀시트를 자동으로 띄우지 않습니다.
- **이탈 방지 팝업 금지**: 뒤로가기 동작 시 사용자 이탈을 가로막는 바텀시트/팝업을 띄우지 않습니다.
- **나갈 수 있는 선택지 제공**: 모든 모달/화면에는 명확한 닫기(X) 또는 취소 방법이 있어야 합니다. 다이얼로그의 취소 버튼 문구는 항상 **'닫기'**로 통일합니다.
- **CTA 명확성**: 버튼 라벨은 행동의 결과를 명확히 알 수 있게 작성합니다 (예: '견적 확인하기', '결제하기', '쿠폰 받기').
- **하단 탭바**: 탭바 구현 시 반드시 토스 표준 **플로팅 탭바(Floating TabBar)** 형태로 구현합니다.
- **SafeArea 준수**: 상단 노치/Dynamic Island 및 하단 홈 바 영역을 침범하지 않도록 여백을 확보합니다.

## 3. 결제 & 광고 & 로그인 규정
- **실물 상품 결제**: 반드시 `TossPay`를 사용합니다 (외부 PG사나 일반 카드결제 모듈 금지).
- **디지털 재화/구독 결제**: 반드시 `IAP`(인앱 결제)를 사용합니다.
- **광고**: 외부 광고 SDK를 직접 넣지 않고 앱인토스 공식 광고(`TossAds`)를 사용하며, 사전에 로딩(`loadFullScreenAd`)하고 광고 재생 중에는 BGM을 일시 정지합니다.
- **로그인**: 토스 로그인(`TossAuth.login`)만 허용됩니다.

## 4. UX 라이팅 (토스 톤앤매너)
- **해요체 100% 사용**: 모든 사용자 대면 텍스트는 해요체로 작성합니다 (`완료되었습니다` ❌ ➔ `완료했어요` ⭕).
- **능동형 & 긍정형 문장**: 피동형(`~되었어요` ❌ ➔ `~했어요` ⭕) 및 부정형(`안 돼요` ❌ ➔ `~하면 할 수 있어요` ⭕)을 피하고 능동적/긍정적으로 표현합니다.
- **과도한 경어 지양**: `~시겠어요?`, `~시나요?`, `~께` 대신 캐주얼하고 친근한 말투(`~해요`, `~에게`)를 사용합니다.
