# 앱인토스 UI/UX, 브랜딩 & TDS 디자인 가이드

앱인토스 미니앱을 설계하고 구현할 때 준수해야 하는 디자인 시스템(TDS), 브랜딩, UX 라이팅 및 다크패턴 방지 가이드라인입니다.

---

## 1. 브랜딩 가이드

### 1-1. 브랜드 로고
- **크기 및 형태**: **600 × 600px의 각진 정사각형** (모서리가 둥근 라운드 형태 ❌).
- **배경**: 반드시 배경이 있어야 하며, 라이트 모드와 다크 모드 모두에서 명확히 식별되는 배경색을 사용합니다.
- **적용 위치**: 앱인토스 콘솔 등록 및 `apps-in-toss.config.ts` (또는 `granite.config.ts`의 `brand.icon`).

### 1-2. 브랜드 이름
- 전체 탭, 알림, 상단 내비게이션, 브릿지 등에 노출됩니다.
- 특별한 사유가 없다면 **한글 표기**를 기본으로 작성합니다 (예: `Toss` ➔ `토스`).

### 1-3. 브랜드 컬러
- 여섯 자리 헥스 코드 (`#3182F6` 등)로 정의합니다.
- 토스 내 진입점, 브릿지 화면, 주요 버튼 색상 등에 적용됩니다.

## 2. 네비게이션 및 레이아웃 설계

### 2-1. 상단 내비게이션 바
- **비게임 앱**: 흰색 배경(기본), 좌측에 로고+이름, 우측에 더보기(⋯)와 닫기(X) 버튼이 위치.
- **게임 앱**: 투명 배경 풀스크린, 우측에 더보기(⋯)와 닫기(X) 버튼 위치.
- **액세서리 버튼 규칙**:
  - 더보기 버튼 왼쪽에 **최대 1개** 추가 가능.
  - **반드시 모노톤 아이콘**만 허용 (컬러 아이콘 금지).
- **뒤로가기 규칙**:
  - 미니앱 자체 뒤로가기 버튼과 토스 네비게이션 뒤로가기가 중복으로 보이지 않도록 구성.
  - 최초 진입 화면에서 뒤로가기를 누르면 미니앱이 종료되어야 함.

### 2-2. 하단 탭바 (Floating TabBar)
- 탭바가 필요한 경우 토스 앱 메인 탭바와 혼동되지 않도록 **반드시 플로팅(Floating) 형태**로 구현합니다.
- 탭 항목 수는 **최소 2개 ~ 최대 5개**로 제한합니다.

### 2-3. 해상도 및 반응형 기준
- **권장 논리 해상도**:
  - 세로형: **360 × 640 ~ 420 × 740**
  - 가로형: **640 × 360 ~ 740 × 420**
- 실제 픽셀 좌표가 아닌 단일 논리 해상도를 기준으로 flex/grid 레이아웃을 구성하고 스케일링 대응합니다.
- **에셋 구성**: 1x(기본) + 2x(고해상도) 에셋으로 준비.
- **Safe Area**: 상단 노치/Dynamic Island, 하단 홈 인디케이터 영역을 침범하지 않도록 내부 여백 적용.

## 3. 다크패턴 절대 금지 정책

사용자의 자율성을 침해하거나 오인을 유도하는 아래 패턴은 검수 반려 및 서비스 차단 대상입니다.

| 위반 유형 | 잘못된 사례 (금지 ❌) | 올바른 설계 (권장 ⭕) |
| :--- | :--- | :--- |
| **진입 즉시 바텀시트** | 앱 열리자마자 이벤트/알림 수신 동의 바텀시트 팝업 | 홈 화면을 먼저 보여주고, 기능 사용 시 맥락에 맞게 안내 |
| **뒤로가기 방해** | 뒤로가기를 눌렀더니 "잠깐만요! 혜택 받으세요" 팝업 노출 | 즉시 이전 화면으로 이동하거나 정상 종료 |
| **선택지 박탈 (트랩)** | 팝업에 "동의하고 계속하기" 버튼만 있고 닫기/취소 없음 | 항상 "닫기" 또는 "다음에 하기" 등 거절/이탈 선택지 제공 |
| **기습 광고 노출** | 아이템 획득 버튼을 눌렀는데 사전 고지 없이 전면 광고 재생 | "광고 보고 2배 받기"처럼 광고 시청 여부를 명확히 표기 |
| **모호한 CTA** | 버튼에 "확인", "계속"만 적혀 있어 다음 화면 예측 불가 | "견적 확인하기", "장바구니 담기", "결제하기"로 명시 |

## 4. UX 라이팅 (토스 톤앤매너 규칙)

### 4-1. 해요체 100% 사용
상황이나 맥락을 불문하고 모든 사용자 대면 텍스트에 **해요체**를 적용합니다.
- `완료되었습니다` ➔ `완료했어요`
- `입력해주세요` ➔ `입력해 주세요`
- `저장되었습니다` ➔ `저장했어요`
- `안내해 드립니다` ➔ `안내해 드려요`

### 4-2. 능동형 문장 사용
수동형/피동형 대신 능동형으로 작성합니다.
- `등록이 완료되었어요` ➔ `등록을 마쳤어요`
- `인증번호가 발송되었습니다` ➔ `인증번호를 보냈어요`
- `~되어요` ➔ `~돼요`

### 4-3. 긍정형 커뮤니케이션
부정적 표현을 줄이고, 사용자가 가능한 대안을 안내합니다.
- `데이터가 없어서 조회할 수 없습니다` ➔ `아직 기록이 없어요`
- `쿠폰을 사용할 수 없어요` ➔ `10,000원 이상 결제할 때 쓸 수 있어요`

### 4-4. 캐주얼한 경어 (과도한 존칭 제거)
- `계시다` ➔ `있다`
- `여쭈다` ➔ `확인하다`, `묻다`
- `~께` ➔ `~에게`
- `~시겠어요?`, `~시나요?` ➔ `~해요`

### 4-5. 한자어 풀이 & 명사 나열 지양
- `입금 완료 후 처리 진행` ➔ `입금하면 바로 처리해 드려요`
- `본인 명의 계좌 등록 필수` ➔ `내 이름으로 된 계좌를 등록해 주세요`

### 4-6. 다이얼로그 버튼 라벨
- 팝업/다이얼로그의 취소/닫기 버튼은 **'닫기'**로 통일합니다 ('취소' ❌).

## 5. 토스 디자인 시스템 (TDS) 핵심 컴포넌트

앱인토스에서는 통일된 경험을 위해 TDS Mobile 컴포넌트 사용을 적극 권장합니다.

| 컴포넌트 | 용도 |
| :--- | :--- |
| **Button** | 주요 액션 버튼 (Primary, Secondary, Weak 등 다양한 계층 제공) |
| **BottomCTA** | 화면 하단에 고정되는 단일/이중 액션 버튼 바 |
| **Top** | 화면 최상단 타이틀, 서브타이틀 헤더 영역 |
| **ListRow** | 리스트 아이템 (좌측 아이콘/텍스트 + 우측 상태/화살표/스위치) |
| **ListHeader** | 리스트 섹션 구분 헤더 |
| **Badge** | 상태, 혜택, 숫자 알림 뱃지 |
| **Paragraph** | 본문 텍스트 타이포그래피 |
| **Tab** | 세그먼트/탭 컨트롤러 |
| **Asset** | 토스 3D 에셋 및 그래픽 표시 모듈 |
| **Border** | 섹션 구분선 및 디바이더 |
